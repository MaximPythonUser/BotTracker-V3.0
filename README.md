
# 🏋️ Training Tracker Bot — Умный трекер тренировок с авто-напоминаниями

**Статус:** Production Ready (готово к деплою)
**Язык:** Python 3.9+
**Стек:** `aiogram 3.x`, `aiosqlite`, `APScheduler`, `pytz`, `python-dotenv`

> «Бот, который не ошибается» — это не просто слоган. Это архитектура, где каждое действие пользователя синхронизировано с базой данных и планировщиком задач. Если тренировка удалена — исчезают и напоминания. Если время изменено — создается новая задача, а старая удаляется. Никаких рассинхронов.

---

## ✨ В чем фишка? (User Flow + Надежность)

Я спроектировал бота так, чтобы минимизировать когнитивную нагрузку на пользователя и исключить ввод некорректных данных, а также добавил слой «умной автоматизации», который отличает этот проект от учебных примеров.

*   **Гибридный ввод и FSM (Машина состояний).** Команда `/edit` показывает список тренировок с кнопками. Пользователь не должен помнить ID записи или вводить сложные команды. Он просто нажимает «Изменить дату», и бот сам подсказывает, что писать дальше.
*   **Защита от мусора (Валидация).** Бот жестко валидирует формат даты (`YYYY-MM-DD`) и времени (`HH:MM`). Если пользователь напишет «завтра» или «семь вечера», бот вежливо попросит исправить формат, а не сохранит ошибку в базу.
*   **Контекстная помощь.** Команда `/start` дает не просто приветствие, а краткую справку с примерами, чтобы пользователь сразу понял синтаксис.
*   **Персонализированное общение.** Бот всегда приветствует пользователя по имени (`first_name`), взятому из профиля Telegram. Это маленькая деталь, которая сильно повышает вовлеченность.
*   **Автоматизация без участия пользователя.** Бот сам планирует напоминания и проверки статуса. Вам не нужно писать код для каждого конкретного времени — логика универсальна.

## 🧠 Нововведения в этой версии (Архитектурные улучшения)

В отличие от предыдущей версии, где логика была линейной, здесь реализована полноценная система управления жизненным циклом задачи.

| Проблема в старых ботах | Решение в этом проекте |
| :--- | :--- |
| **Рассинхрон БД и Планировщика.** При удалении тренировки напоминание могло остаться висеть в планировщике и сработать позже. | **Жесткая синхронизация.** При удалении тренировки (`/delete` или кнопка «Удалить») бот программно удаляет соответствующие задачи из APScheduler (`reminder_*` и `check_*`). |
| **Потеря задач при рестарте.** Если бот перезагружался, все запланированные напоминания исчезали. | **Восстановление расписания.** Функция `schedule_existing_reminders()` при каждом запуске сканирует базу данных и восстанавливает все активные задачи. |
| **Дублирование напоминаний.** При редактировании времени старое напоминание могло остаться, и пользователь получал два сообщения. | **Умный рефакторинг задач.** При изменении времени тренировки старое напоминание удаляется, и создается новое с актуальным временем. |
| **Блокировка потока.** Синхронная работа с БД могла «заморозить» бота при высокой нагрузке. | **Асинхронность.** Используется `aiosqlite` для неблокирующего доступа к базе данных. |

## 🛠 Технологии и архитектура

*   **Aiogram 3.x:** Современный асинхронный фреймворк для создания Telegram-ботов.
*   **APScheduler:** Надежный планировщик задач для отложенных сообщений (напоминания за 20 минут и проверка статуса через час).
*   **aiosqlite:** Асинхронный интерфейс к SQLite, предотвращающий блокировку event loop.
*   **FSM (Finite State Machine):** Машина состояний для пошагового редактирования данных тренировки.
*   **pytz:** Корректная работа с часовыми поясами (Europe/Moscow), чтобы напоминания приходили вовремя независимо от сервера.
*   **python-dotenv:** Безопасное хранение токена бота в файле `.env`.

## 📂 Структура данных и масштабируемость

Данные хранятся в SQLite. Ключевое поле — `user_id`. Это позволяет масштабировать решение: сегодня бот работает для одного человека, завтра — для тысячи, и данные не перемешаются.

Таблица `one_off_trainings` хранит всю необходимую мета-информацию:
*   `id`: Уникальный идентификатор задачи (используется для генерации ID задач в планировщике).
*   `user_id`: Владелец тренировки.
*   `date`, `start_time`: Время события (хранится отдельно для удобства редактирования).
*   `training_name`: Название тренировки.

## 📋 Функционал

*   **/add ГГГГ-ММ-ДД Название ЧЧ:ММ** — добавить тренировку. Бот проверит, не прошла ли дата, и запланирует напоминание и проверку.
*   **/my_trainings** — посмотреть список своих тренировок с нумерацией.
*   **/edit** — выбрать тренировку из списка и отредактировать только дату, только время или название через пошаговый диалог.
*   **/delete <номер>** — удалить тренировку по номеру из списка.
*   **Inline-кнопки после тренировки:** После истечения времени проверки бот присылает кнопки: «✅ Прошла», «🗑 Удалить», «🔄 Перенести».
